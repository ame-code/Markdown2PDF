# 06 · 增量阶段：书签、字体、数学公式、代码高亮、TOC

## 观察与实现

### 6.1 书签大纲（outline）

Typora 不自己算标题位置，而是**利用 Chromium 打印时为不可见锚点生成的链接注释**：

- 每个标题带的 `<a href="af://n<cid>">`（`display:block;position:absolute;width:1px`）会在 PDF 里
  生成 `/Link` 注释，`/A/URI = af://n<cid>`，`/Rect` 就是标题在该页的位置。
- frame.js 用 `c(e)` 扫描每页 `node.Annots()`，取 `URI` 匹配 `^af://(.+)$` 的注释，
  算出 `id → [页码+1, pageHeight - rect.height - rect.y]`。

本工具（`src/postprocess.js`）：

```js
extractAnchors(doc)   // Map(cid → {page, top})，扫 /A/URI 前缀 af://
addOutline(doc, entries) // 按 level 建 /Outlines 树
```

写出的字典结构与 Typora 一致：`/Title` 用 `PDFHexString`（中文安全）、
`/Dest [pageRef /XYZ null top null]`、`/Parent /First /Last /Prev /Next /Count`，
并在 catalog 上设 `/PageMode /UseOutlines`（打开 PDF 默认显示书签栏）。

验证：金标准 `get_toc()` = `[[1,'Heading 1',1],[2,'Heading 2',1]]`，
本工具输出相同；多页文档 8 个标题、三级嵌套、页码跨页正确：

```
[[1,'第一部分',1],[2,'1.1 小节',1],[3,'1.1.1 更小的小节',1],[2,'1.2 第二个小节',2],
 [1,'第二部分',2],[2,'2.1 二级',2],[2,'2.2 另一个二级',2]]
```

### 6.2 自定义字体

- `my.css` 的 `@font-face` 全部叫 `'JetBrains Mono'`，但 regular 面指向
  `./github/open-sans-v17-latin-ext_latin-regular.woff2`（**Open Sans**），
  bold/italic 用 `local()` 拿不到 → 合成粗体/斜体。
- 工具把 4 个 woff2 一起 vendor 到 `vendor/themes/github/`，CSS 里的相对路径因此可解析
  （这也是必须保留 `themes/` 目录层级的原因）。
- 打印前等待 `document.fonts.ready`，避免用回退字体量了宽度就打印。
- 主题里的 `@include-when-export url(https://fonts.googleapis.com/…)` **不复刻**：
  Typora 只是插了个外链，本地 woff2 兜底；断网环境反而更稳。

### 6.3 数学公式（MathJax 3 `tex-svg`）

- 直接使用 Typora `lib.asar` 里的 MathJax 3.2.2 bundle（`tex-svg-full.js`）与 Typora 的配置
  （`startup.typeset:false`、`fontCache:'local'`、`display metrics {containerWidth:783, scale:80}`、
  `enableAssistiveMml` 导出时剔除、`tags:'none'`）。
- **目录结构不能拍平**：配置里有 `loader.load:['input/tex/extensions/xypic']`，
  是相对 bundle URL 解析的，所以 `src/math/vendor/` 下必须同时存在
  `tex-svg-full.js` 与 `input/tex/extensions/xypic.js`；页面必须是 `file://`。
- 产物与金标准**逐字节相同**（`src/math/verify.js` 17/17）：
  行内 `8.699ex × 2.072ex`、`viewBox="0 -833.9 3845.1 915.9"`、`vertical-align:-0.186ex`；
  块级 `16.809ex × 6.354ex`、`viewBox="0 -1562.5 7429.7 2808.5"`、`vertical-align:-2.819ex`。
- 样式表 `MATH_CSS`（2,688 字符）= `MathJax.svgStylesheet()`，`MATH_PRINT_STYLE`（2,835 字符）
  = `html {overflow-x: initial !important;}` + CSS + `path[data-c]{stroke-width:0}`，
  与金标准 `<style>` 一致。
- `MJX-<n>-…` 里的 n 是 MathJax 每次排版自增的计数器（Typora 里受编辑历史影响，金标准是块 1、行内 3）。
  对像素无影响；需要 HTML 逐字节时可以传 `localID` 固定。

### 6.4 代码高亮（CodeMirror 5）

- 用 Typora 自己的 CodeMirror 5 + `mode.min.js` + 激活行插件，主题类保持
  `cm-s-inner cm-s-null-scroll CodeMirror-wrap`，外层
  `<pre class="md-fences md-end-block ty-contain-cm modeLoaded" … lang="cpp">`。
- 导出机器的显示器缩放是 **125%**，因此内层行盒是 23.0375px 而不是 23.04px
  （产物里 `top: 9.51875px`），工具把 `displayScale` 默认设为 1.25 复刻。
- `lang=""` 一定输出（`<pre>` 上原样、内层容器小写化）；`modeLoaded` 一定在；
  `md-fences-with-lineno` 只在开启行号时出现；代码块上**从不**出现 `data-breakpage`。
- 验证：`node src/fence/verify.js` 输出的 `<pre>` 与实机产物 **逐字节相同**
  （2,069 B，sha256 `e0bbc1ad…34a8da`），14/14 通过。
- frame.js 里那段「把 `;` 和 `-` 包一层 font-family span」的代码在实机产物里没有生效
  （它对 Text 节点赋 `.innerHTML`，是无效操作），工具**故意不复刻**。

### 6.5 页眉 / 页脚

- 与 Typora 同构：把每页的页眉文字渲染成**一页一个段落**的 HTML，
  用 `paperWidth = 页面宽/72`、`paperHeight = 30/72` 英寸、四边 margin 0 打印成一条 30 pt 高的纸条，
  再把纸条页贴到内容页的顶部（`y = pageHeight-30`）/底部（`y = 0`）。
- 段落样式照抄 frame.js：
  `font-size:12px;text-align:center;margin:0;padding:0 ${right}px 0 ${left}px;
   height:${(30-8)×1.3281472327365}px;line-height:同样值;page-break-before:avoid;
   page-break-after:always`，内部 `<span style="display:inline-block;vertical-align:middle">`。
- 验证：金标准页脚 `'No. 1 / 1'` 在 `[273.82, 817.20, 322.42, 829.08]`、9.00 pt JetBrainsMono-Regular；
  本工具输出**完全相同**（含字族、字号、位置）。

### 6.6 TOC 与目录页码

实机产物里没有 `[TOC]` 样本，但 `base.css` 里留着 Typora 完整的 `.md-toc*` 样式，
所以「用同一套类名、让主题 CSS 生效」比重建一套排版更可靠（字号 `.9rem`、每级缩进 2em、
颜色 `#4183c4` 全部继承）。页码实现为两遍渲染 + 迭代收敛，来源是 Chromium 为
`href="#header-nX"` 生成的链接注释（`kind=4`，`page` 已解析），与书签同源。
细节见 `report/07-TOC与页码.md`；校验器 `tools/toc_check.py` 验「行数 = 书签数、
链接目标页 = 书签页码、打印数字 = 链接目标页」三重一致。

### 6.7 覆盖性回归（`test/features.md`）

一份把所有构造堆在一起的文档，用来防止单项修复互相破坏。构建命令：

```bash
node bin/md2pdf.js test/features.md -o out/features.pdf --footer "${pageNo} / ${totalPages}"
```

验证结果（`out/png-features-1.png`）：h1–h6 字号/下边框/颜色分级正确；任务列表渲染成
勾选/未勾选复选框且 `md-task-list-item task-list-item task-list-done|not-done` 类名齐全；
`1. 2.` + `-` 嵌套缩进正确；三列对齐表格（`:---` / `:---:` / `---:`）中线与右边线分别对齐；
行内 `\frac` 与 `\sqrt` 与正文同基线；`aligned` 多行公式居中且未套 `displayLines` 死行保护；
python 代码块高亮与行盒正确；脚注引用上标 + 文末 `footnotes-area`（含 `<hr/>`）出现；
`---` 分隔线、页脚页数均正确。书签覆盖到 6 级：`[[1,'一级标题',1],…,[6,'六级标题',1]]`。

## 决策

1. 书签位置**复用 Chromium 的锚点注释**，不做文本抽取/坐标猜测 —— 与 Typora 同一机制，
   因此页码与纵坐标天然一致。
2. 数学与代码块**不重写渲染器**，而是内置 Typora 同版本库，减少「看起来差不多但像素差一点」的风险。
3. 页眉页脚走「独立纸条页面 + 叠加」，与 Typora 完全同路径，避免自己算文字垂直居中。
4. 元数据按 Typora 的怪癖写：`Creator="Typora"`、`Producer="Typora, Electron"`、
   `CreationDate` 是无 `D:` 前缀的 `YYYYMMDDHHmmSS`、`ModDate` 是 `D:…Z`。

## 未解决风险

- `MathJax` 的 `MJX-<n>` 计数、`xypic` 扩展路径属于「脆弱依赖」，升级 Typora 后需重新抽取。
- `[TOC]` 的条目结构是按 Typora 自带 CSS 重建的，与编辑器内实际 DOM 不保证逐像素一致；
  脚注区结构未做像素级验证。
- 页眉页脚宽度为 0 时（`marginLeft == marginRight`）Typora 会把左右 padding 归零，
  本工具照抄该逻辑，但只在默认 `paper.margin` 下验证过。
- 书签在大纲项超过数百个时未做 `/Count` 递归深度回归。
