# 04 · 阶段 3：DOM 快照规范

## 观察

阶段 1 的静态分析结论与「Typora 实机导出的打印 HTML」逐条对照后，得到下面这份规范
（完整版 660 行在 `evidence/dom-spec.md`，可执行的 28 条 fixtures 在 `evidence/dom-cases/cases.json`）。

### 4.1 外壳与拼接方式

- `<body class="typora-export typora-print os-windows">`，内层 `<div class="typora-export-content">`，
  再内层 `<div id="write" style="top:auto" class="is-node">`。
- **块与块之间零分隔符**（打印模式下分隔符变量是空串），整个文档里唯一的换行是引用内部的软换行。
- 文件末尾没有多余换行；`<title>` 取元信息 title 或文件名，且**PDF 元数据 Title 默认为空**。

### 4.2 核心修正（静态分析看不出来、必须靠快照校正的）

1. **纯文本必须包 `<span>`**，包括行内元素之间的空格；
   但 `<code>`、`<img>`、`<mjx-container>`、`<hr />` 不包。
2. **标题在打印模式下是 `<a name>`，不是 `id`**：
   `<h1><a name="header-n0" class="md-header-anchor md-print-anchor" href="af://n0"> </a><span>Heading 1</span></h1>`；
   HTML 导出模式恰好相反（有 `id`、无 `<a>`）。这个 `<a>` 是书签定位的唯一依据。
3. **`data-breakpage` 在 PDF 里是死属性**。frame.js 里 `splitPages` 只出现在 `T()` 中，
   而 PDF 导出从不传 `splitPages`，所以 `[data-breakpage]{page-break-before:always}` 这条规则
   **永远不会被注入**。→ 逐字复刻：属性照写（第二个及以后的顶层 H1、脚注区），规则永不注入。
4. **表格单元格的属性形状**是 ` style='text-align:left;' `（分号在引号内、引号后有空格）。
5. **代码块内层容器一定带 `lang`（可为空串）**，`modeLoaded` 一定在，
   `md-fences-with-lineno` 只在开启行号时出现。
6. **块级公式保留编辑器属性**（`cid`、`mdtype`、`data-math-tag-*`、`data-math-labels`），
   行内公式则只有 `<mjx-container>` + `<script type="math/tex">`。
7. 图片：`<img src="file:///…?lastModify=<ts>" referrerpolicy="no-referrer" alt="…">`，
   `?lastModify` 是导出瞬间的时间戳（不是文件 mtime）。
8. 空段落 → `<p>&nbsp;</p>`；空单元格 → `&nbsp;`；`hr` → `<hr />`。

### 4.3 cid 与锚点

- 锚点名形如 `af://n0`、`af://n2`、`af://n4`…… 来自 `"n" + 计数器`，计数器在编辑器里
  **连行内节点也会自增**，因此无法从 Markdown 精确反推（真实样例里标题是 n0/n2，
  块公式却是 n27）。
- 决策：**每个块分配 2 个 cid**。这样 `# Heading 1` → `n0`、`## Heading 2` → `n2`，
  与真实产物一致；块公式的 `mathjax-n27` 对不上，但该 id 打印时不可见、也不影响像素与书签
  （书签位置来自注释矩形，不来自编号）。

### 4.4 行内与特殊节点

| Markdown | 输出 |
| --- | --- |
| `**b**` / `*i*` / `~~d~~` | `<strong><span>…</span></strong>` / `<em>…` / `<del>…` |
| `` `c` `` | `<code>c</code>` |
| `[t](url)` | `<a href='url'><span>t</span></a>`（外部 URL 的 `&` 转义为 `&amp;`） |
| `[t](#目标)` | 内部链接解析成 `href='#header-n<cid>'`（Windows 语义） |
| 换行（`\n`） | 软换行 → 字面 `\n`；硬换行（行尾两空格）→ `<br/>` |
| 转义 | `& < > " '` → `&amp; &lt; &gt; &quot; &#39;` |
| 任务列表 | `<li class='md-task-list-item task-list-item task-list-done\|task-list-not-done' ><input type='checkbox' checked\|/>` |
| 脚注 | 引用 `<sup class='md-footnote'><a href='#dfref-…' name='ref-…'>1</a></sup>`；文末 `<div class='footnotes-area' data-breakpage ><hr/><div class='footnote-line'>…` |
| YAML front matter | 丢弃 |

### 4.5 打印 CSS 的三段式

`<style>` 内容 = `html {overflow-x: initial !important;}` + （有公式时）MathJax 样式表 + 标题 `::after` 规则。
用 `my.css` 时只有 h3–h6 命中（h1/h2 有下边框被排除），样例文档只用了 h1/h2 → 该段为空，
与产物一致。

## 决策

1. 以**实机产物优先于代码**：凡代码与产物冲突（空白折叠规则、`data-breakpage`），一律跟产物。
2. DOM 元素必须**逐字符**匹配才有意义，因为主题 CSS 依赖类名与层级的精确组合
   （例如 `.md-fences code` 的 padding、`figure.table-figure` 的 `zoom` 修正脚本）。
3. 代码块与公式不自己拼 HTML，而是**在浏览器里用 Typora 同款库真实渲染**
   （CodeMirror 5 / MathJax 3.2.2），这样 DOM 与 CSS 由库自己保证一致 —— 见 `report/06`。
