# 03 · 阶段 2：主题 CSS 与打印规则

## 观察

### 2.1 `my.css` 的实际效果（8,557 B / 416 行）

```css
@include-when-export url(https://fonts.googleapis.com/css?family=Open+Sans:400italic,700italic,700,400&subset=latin,latin-ext);
@font-face { font-family:'JetBrains Mono'; src:url('./github/open-sans-v17-latin-ext_latin-regular.woff2') format('woff2'); unicode-range:…; }
@font-face { font-family:'JetBrains Mono'; font-style:italic;  src:local('JetBrains Mono Italic')  format('ttf'); … }
@font-face { font-family:'JetBrains Mono'; font-weight:bold;  src:local('JetBrains Mono Bold')    format('ttf'); … }
@font-face { font-family:'JetBrains Mono'; font-weight:bold; font-style:italic; src:local('JetBrains Mono Bold Italic') format('ttf'); … }

html  { font-size:16px; -webkit-font-smoothing:antialiased }
body  { font-family:"JetBrains Mono","Clear Sans","Helvetica Neue",Helvetica,Arial,'Segoe UI Emoji',sans-serif;
        color:rgb(51,51,51); line-height:1.6 }
#write{ max-width:860px; margin:0 auto; padding:30px; padding-bottom:100px }

```

- 四个 `@font-face` **同名** `'JetBrains Mono'`，但只有 regular 指向真实文件
  （`github/open-sans-v17-…regular.woff2`，即 **Open Sans**）；italic/bold/bold-italic
  用 `local('JetBrains Mono Xxx') format('ttf')`，本机没有该字体 → 浏览器回退到 regular 面
  并合成斜体/粗体。**这就是为什么「JetBrains Mono」实际渲染成 Open Sans + 合成粗斜体。**
- 标题：`h1..h6{position:relative;margin:1rem 0;font-weight:bold;line-height:1.4}`；
  `h1{font-size:2.25em;line-height:1.2;border-bottom:1px solid #eee}`，`h2{1.75em/1.225 + border-bottom}`，
  h3 1.5em/1.43、h4 1.25em、h5 1em、h6 1em 且 `color:#777`。
- 间距：`p,blockquote,ul,ol,dl,table{margin:0.8em 0}`；`li>ol,li>ul{margin:0}`；
  `ul,ol{padding-left:30px}`；`blockquote{border-left:4px solid #dfe2e5;padding:0 15px;color:#777}`；
  `hr{height:2px;margin:16px 0;background:#e7e7e7;border:0}`。
- 表格：`tr{border:1px solid #dfe2e5}`、`tr:nth-child(2n),thead{background:#f8f8f8}`、
  `th/td{padding:6px 13px}`、`th{border-bottom:0}`。
- 代码：`.md-fences,code,tt{border:1px solid #e7eaed;background:#f8f8f8;border-radius:3px;
  padding:2px 4px 0;font-size:0.9em}`；`code{background:#f3f4f4;padding:0 2px}`；
  `.md-fences{margin:15px 0;padding-top:8px;padding-bottom:6px}`；`.CodeMirror-lines{padding-left:4px}`。

### 2.2 主题里的 print / @page / break 规则

| 类别 | 内容 |
| --- | --- |
| `@media print` | `html{font-size:13px}`、`pre{page-break-inside:avoid;word-wrap:break-word}` |
| `@page` | **主题内没有**（Typora 只在 `paper.margin==="custom"` 时才注入 `@page`，默认没有） |
| `break-*` | 主题内没有 |
| `page-break-*` | 仅上面那条 `pre{page-break-inside:avoid}` |
| `widows`/`orphans` | 无 |
| 注释掉的 | 第 135–150 行有一段被注释的 `@media print{ .typora-export h1,h2{…} }`，不生效 |

打印时 `html{font-size:13px}` 是**最关键的一条**：所有 em 尺寸都按 13px 计算，
而不是屏幕上的 16px。这就是「打印看起来比屏幕小一圈」的来源。

### 2.3 来自 Typora 自身的打印 CSS（不在主题里，在 frame.js 里拼）

1. `<style>` 开头固定 `html {overflow-x: initial !important;}`。
2. 文档里有 `mjx-container` 时：整份 MathJax `svgStylesheet()` + 一条
   `mjx-container[jax="SVG"] path[data-c], use[data-c] { stroke-width: 0; }`。
3. 标题占位规则（按当前主题**逐级探测**决定）：
   若 `#write hN` 的 computed `border` 以 `0px` 开头、`outline` 以 `0px` 结尾、
   `boxShadow`/`backgroundImage` 为 `none`、`backgroundColor` 透明、且 `hN::after` 的 `content` 不为 `none`，
   则注入 `.typora-export hN::after {content:"";display:block;height:100px;margin-bottom:-100px;}`。
   → `my.css` 下 h1/h2 因 `border-bottom` 被排除，h3–h6 又因主题没有定义 `::after` 内容
   （`getComputedStyle(h,'after').content === 'none'`）而全部不命中，所以实际**一条都不会注入**。
   Typora 仍会执行这段探测，只是结果为空 —— 工具同样探测、同样为空。
4. `data-breakpage` 打印规则：**PDF 导出路径不注入**（`splitPages` 参数从没被传入），
   所以 `data-breakpage` 属性在 PDF 里是死属性（详见 `report/04`）。
5. `File.option.preLinebreakOnExport` 为真时不注入空白折叠规则；默认值是 `false`（应当注入）
   但**录到的产物里没有这条规则** —— 本工具跟随产物。

不需要改写任何一条规则。

## 决策

1. **不改主题 CSS**，一个字都不改；工具的责任是产出正确 DOM。
2. 打印 CSS 按 frame.js 的判定逻辑**在浏览器里现算**：页面加载完、内容渲染后，
   对实际存在的 h1–h6 逐一探测 computed style（`border` 以 `0px` 开头、`outline` 以 `0px` 结尾、
   `boxShadow`/`backgroundImage` 为 `none`、`backgroundColor` 全透明、`::after` 的 `content` 非空），
   命中才注入对应规则（实现见 `src/build.js`）。用 `my.css` 时**没有任何一级命中**
   （主题没有给标题定义 `::after` 内容），因此样例文档的打印 CSS 里这一段为空 —— 与产物一致。
3. MathJax 样式表**只在文档含公式时**注入（与 Typora 一致），内容由 `src/math/` 直接产出，
   与金标准 `<style>` 逐字节相同（2,835 字符）。
4. `@page` 一律不注入，交给 Chromium 默认边距。

## 未解决风险

- 空白折叠规则的矛盾（`preLinebreakOnExport`）——已按产物实现，若换主题或换版本需重新采样。
- `my.css` 里的 `@include-when-export` 会让 Typora 在导出时额外插一个 Google Fonts 链接；
  Typora 因为有 `./github/*.woff2` 兜底，实际不联网。本工具**不复刻这个外链**
  （否则断网环境会阻塞渲染），字体完全走本地 woff2；像素验收表明两者无差异。
