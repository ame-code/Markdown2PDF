# 02 · 阶段 1：静态逆向导出调用链

## 观察

### 1a) printToPDF 的调用点与完整 options

`frame.js` 的 `exportPDF`（约 726058–730508）里，主内容打印是：

```js
await JSBridge.invoke("export.printToPDF", tempHtmlPath, {
  printBackground: false,
  marginsType: 0,
  pageSize: "A4"
});
```

真实录到的 IPC（`reverse-typora-export\evidence\ipc-real-printtopdf-calls.json`）与此一致：

```
call 1: export.printToPDF(<temp>.html, {printBackground:false, marginsType:0, pageSize:"A4"})
call 2: export.printToPDF(<temp>.html, {
          printBackground:false,
          marginsType:1,
          margins:{top:0,bottom:0,left:0,right:0},
          pageSize:{width:8.276666388888888, height:0.41666666666666663}
        })
recordLastExport({path:…, type:"pdf", footer:"No. ${pageNo} / ${totalPages}", author:"一苇"})
```

- `marginsType` / `pageSize` 是 **Electron 老 API** 的写法。在 Electron 30 里
  `marginsType` 已经无效（是个被忽略的键），`pageSize:"A4"` 被转换为
  **595.92 × 842.88 pt**（= 8.276666… × 11.706666… 英寸，A4 的 210×297 mm 按 72/25.4 折算）。
- 没有传 `margin`，所以 Chromium 用**自己的默认打印边距 1 cm（28.35 pt）**。
  这也是金标准里正文左上角从 (74.5, 37.87) 开始的原因。
- 页眉/页脚 pass 显式传 0 边距，因为它是「一条 30 pt 高的纸条」，默认 1 cm 边距
  会把纸纸条内的内容挤出去（这个坑我们在阶段 4 真实踩到，见 `report/05`）。

对应到 CDP（Playwright/Puppeteer 的底层）：

```js
{
  printBackground: false,
  preferCSSPageSize: false,
  paperWidth: 595.92 / 72,      // 8.276666666666667 英寸
  paperHeight: 842.88 / 72,     // 11.706666666666667 英寸
  // 不传 margin* → Chromium 默认 1 cm，与 Typora 一致
}
```

### 1b) 导出用的是「重新生成的打印 DOM」

`exportToHTML(options)` 从编辑器文档树（`File.editor.export.exportCollection(blocks,…)`）
重新序列化，而不是抓编辑器当前 DOM。证据：

- `exportToHTML` 里对每个节点按 `case A.heading / paragraph / table / hr / …` 重新拼 HTML；
- 打印模式会给根容器加 `is-node`、给 body 加 `typora-export typora-print os-windows`；
- 编辑器 DOM 才有的 `cid` / `mdtype` / `md-end-block` 等属性在正文节点上被**剥掉**，
  但**块级公式例外**（保留了 `cid="n27" mdtype="math_block" data-math-*`）。

### 1c) Markdown → HTML 的关键结构

外壳（frame.js 721000–721500）：

```html
<!doctype html>
<html>
<head>
<meta charset='UTF-8'><meta name='viewport' content='width=device-width initial-scale=1'>
<link rel='stylesheet' href='…base.css' type='text/css' /><link … codemirror.css … /><link … my.css …>
<style type='text/css'>html {overflow-x: initial !important;}…</style><title>…</title>
</head>
<body class='typora-export typora-print os-windows'><div class='typora-export-content'>
<div id='write' style='top:auto' class='is-node'>…</div></div>
<script>…setBreakPage…</script><script>…figure>table zoom…</script></body>
</html>
```

正文节点（全部**无分隔符**直接拼接）：

| 结构 | 打印模式输出 |
| --- | --- |
| 根容器 | `<div id="write" style="top:auto" class="is-node">` |
| 标题 | `<hN><a name="header-n<cid>" class="md-header-anchor md-print-anchor" href="af://n<cid>"> </a><span>…</span></hN>`（**无 `id`**） |
| 段落 | `<p><span>文本</span>…</p>`（纯文本必须包 `<span>`） |
| 行内代码 | `<code>inline code</code>`（**不**包 span） |
| 引用 | `<blockquote><p><span>…</span>\n<span>…</span></p></blockquote>` |
| 列表 | `<ul><li><p><span>…</span></p></li></ul>`；有序 `<ol start='' >` |
| 表格 | `<figure class='table-figure'><table><thead>…<th style='text-align:left;' >` |
| 代码块 | `<pre class="md-fences md-end-block ty-contain-cm modeLoaded" spellcheck="false" lang="cpp">` + 完整 CodeMirror 5 DOM |
| 块公式 | `<div contenteditable="false" spellcheck="false" class="mathjax-block md-end-block md-math-block md-rawblock" id="mathjax-n<cid>" cid="n<cid>" mdtype="math_block" data-math-tag-before="0" data-math-tag-after="0" data-math-labels="[]">` |
| 行内公式 | `<mjx-container class="MathJax" jax="SVG" style="position: relative;">…<script type="math/tex">E = mc^2</script>` |
| 图片 | `<p><img src="file://…?lastModify=…" referrerpolicy="no-referrer" alt="image"></p>` |
| 分隔线 | `<hr />` |
| 元信息块 / 链接定义 | 空字符串 |

## 决策

1. 工具不复用 Typora 的 `Node.prototype.toHTML`：它依赖编辑器模型、`File.option`、
   `File.inBusyMode`、`#md-rawblock-tooltip-templ` 等运行时状态，无法离体使用。
   改为用 markdown-it 重写解析器，**按上表逐条对齐输出形状**。
2. 打印参数按 CDP 的 `paperWidth/paperHeight` 传英寸，不传 `format:'A4'`（见 `report/05` 的坑 1）。
3. 不传 margin，让 Chromium 保留默认 1 cm —— 这正是 Typora 的实际结果。

## 未解决风险

- Electron 版本升级后 `marginsType` 之外的语义可能变化；本工具不依赖 Electron，
  只依赖 CDP 参数，因此受影响面更小。
- `preLinebreakOnExport` 分支与实机产物矛盾（见 `report/03` 与 `report/00` 风险 1）。
