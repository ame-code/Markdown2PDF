# 05 · 阶段 4：独立工具与逐页比对

## 观察（实现要点）

技术栈：**Node.js 24 + puppeteer-core + Chromium 124 + markdown-it + pdf-lib**。
不用 Playwright（原生 playwright 会改写打印参数），不用 pandoc，不用 Electron。

流水线（`src/build.js`）：

```
Markdown --markdown-it--> 打印 DOM（含代码块/公式占位）--> 临时 HTML（file://）
   --Chromium 124: 真实渲染 CodeMirror + MathJax--> 回填占位
   --CDP Page.printToPDF{paperWidth,paperHeight}--> 原始 PDF
   --pdf-lib: 页眉/页脚贴页 + 书签大纲 + 元数据 --> 最终 PDF
```

## 踩过的坑（全部是实测定位，不是猜测）

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | Puppeteer `page.pdf({format:'A4'})` 整体偏移 28 pt | Chromium 的「A4」命名纸张 ≠ Electron `pageSize:"A4"`（595.92×842.88 pt） | 直接传 `paperWidth/paperHeight`（英寸），`preferCSSPageSize:false` |
| 2 | 传 `margin:0 / 1cm / 28pt` 输出完全一样 | 内容那一遍 Typora 没传 margin，Chromium 用默认 1 cm；`marginsType` 在 Electron 30 已是无效键 | 内容页**不传** margin；只有页眉页脚纸条传 0 |
| 3 | 页脚跑到页面**顶部** | 页眉/页脚是「30 pt 高的独立页面」，Chromium 默认 1 cm 上下边距（共 56.7 pt）把 30 pt 的纸挤爆，内容被顶到纸外 | 页眉/页脚 pass 传 `marginTop/Bottom/Left/Right = 0`（= Typora 的 `marginsType:1, margins:0`） |
| 4 | 代码块比金标准高 23.04 px，其后所有内容下移 14.25 pt | markdown-it 的 fence `content` 结尾带 `\n`，CodeMirror 多渲染一条空行 | `stripFenceTail()` 去掉结尾换行 |
| 5 | 公式一直报 `MathJax is not initialized` | Typora 配置 `startup.typeset:false`，bundle 加载后 startup 是异步完成的 | 渲染前 `await MathJax.startup.promise` + 轮询 `startup.document && tex2svgPromise` |
| 6 | `md2pdfRenderMath: no inline placeholder for index 0` | `renderDocument` 两遍扫描（第一遍收集标题 cid 以便解析内部链接）**两遍都调了 hooks**，占位下标被翻倍 | 第一遍改传 `inertHooks`（返回空串、不登记 payload） |
| 7 | `$$ … $$` 被当成普通段落 | markdown-it 默认没有块公式规则 | 新增 `blockMathPlugin`（`md.block.ruler.before('fence','math_block',…)`） |
| 8 | 首行 `# 标题` 被当成段落 | PowerShell `Set-Content -Encoding utf8` 写了 BOM | `stripBom()` |
| 9 | 页脚字体/颜色与正文不一致时的兜底 | 页眉页脚需要知道正文字体与颜色 | 打印前读 `#write` 的 computed style（`fontFamily` 首项、`color`） |

## 证据位置

- 引擎与参数：`src/print.js`（`A4 = 595.92/72 × 842.88/72`，裸 CDP）
- DOM 生成：`src/md2typora.js`、`src/template.js`
- 页面叠加/元数据/书签：`src/postprocess.js`、`src/bands.js`
- 验收脚本与阈值：`tools/acceptance.mjs`、`tools/pdfdiff.py`（150 dpi 分带像素比对）
- 差异报告：`out/acceptance-diff.json`
- 诊断工具：`tools/_spans.py`（逐 span 坐标）、`tools/geom.mjs`（DOM 盒模型）、
  `tools/dump-annots.mjs`（链接注释）、`tools/probe-margins.js`（边距探针）
- 视觉对比：`out/png-v6/A-p1.png`（本工具）vs `B-p1.png`（金标准）

## 决策

1. **只用裸 CDP `Page.printToPDF`**，不用 Puppeteer 的 `page.pdf()` —— 后者会注入
   `format`/`margin` 语义并改写页尺寸，是上述坑 1/2 的根源。
2. 渲染分两阶段：先出静态 HTML，再在同一个 `file://` 页面里跑 CodeMirror / MathJax 回填，
   **最后才打印**，保证打印时 DOM 已经是终态（Typora 也是这么做的）。
3. 代码块与公式的 DOM 交给库自己生成（CodeMirror 5 / MathJax 3.2.2），我们只负责
   「同版本、同配置、同容器类名」。
4. 后处理用 pdf-lib 低层 API 手写大纲字典（pdf-lib 没有 outline API）。

## 未解决风险

- Chromium 版本被钉死为 124。用 153 时同一份 HTML 出现 0.775% 正文差异
  （`U+21A9` 等符号回退到 SegoeUISymbol 而不是 CambriaMath）。工具启动时会优先用
  `--chrome` 指定路径，默认指向本机 ms-playwright 的 chromium-1112。
- 页眉页脚的字体只取「正文首个字族」，Typora 是取 `printToPDF` 分析出的文本样式；
  本项目语料下结果一致，复杂字体栈可能不同。
- 单页/两页语料已逐像素验证；超长文档（数百页）尚未做性能与分页回归。
