# 09 · 用自写样式表替换 Typora 专有 CSS

## 背景

工具原本直接复用 Typora 安装目录里的 `D:\Typora\resources\style\base.css`（13,312 B）
与 `codemirror.css`（4,453 B）。这两份文件是 Typora 的产品组成部分，跟着程序一起分发
属于再分发第三方专有资源，许可上不干净。

目标是：**像素输出保持 0.0000% 不变**，但包里不再出现这两个文件。

## 观察

### 9.1 这两份样式表里真正参与打印的规则有多少

用 `tools/css-audit.mjs` 打开真实打印态 DOM（`Emulation.setEmulatedMedia({media:'print'})`），
对每条 `CSSStyleRule` 统计 `document.querySelectorAll(selectorText).length`，
五份样本取并集：

| 样式表 | 规则总数 | 命中（live） | 命中 0 | 仅屏幕态 `@media` |
| --- | --- | --- | --- | --- |
| `base.css` | 202 | **78** | 116 | 8 |
| `codemirror.css` | 77 | **31** | 46 | 0 |

即约 61% 的规则在打印路径里完全用不上（屏幕态 toggle、菜单、大纲侧栏、滚动条装饰、
`@media screen and (max-width:500px)` 分支等）。live 规则共 109 条。

### 9.2 三处必须小心的语义

1. **同一选择器会被声明多次**，靠源码顺序做层叠覆盖。例如 `base.css` 里
   `p { orphans: 4 }` 与 `p { line-height: inherit }` 是两条独立规则；
   `codemirror.css` 里 `.CodeMirror { position: relative; overflow: hidden }`
   与后面的 `.CodeMirror { height: auto }` 也是两条。按选择器去重会把前者整个吃掉。
2. **规则顺序不能重排**。`.CodeMirror-wrap pre { overflow-wrap: break-word }` 之后
   还有 `.CodeMirror pre { overflow-wrap: normal }`，后者覆盖前者；一旦按“分节”重排
   （哪怕只是把同类规则聚在一起），计算值就变了。
3. **样本必须覆盖全部构造**。第一轮样本（features / toc / large / fence）里都没有图片，
   于是 `img { max-width: 100% }`、`p > img:only-child { display: block; margin: 0 auto }`
   被判为“命中 0”删掉 —— 图片块立刻变宽，整页下移 6.8 px，像素差 4.07%。

## 实现

### 9.3 审计器 `tools/css-audit.mjs`

- 逐个样本 `goto(file://…)` → `Emulation.setEmulatedMedia({media:'print'})`；
- 原始样式表**从磁盘读**（`evidence/css-originals/`），用 `new CSSStyleSheet().replaceSync(text)`
  解析后遍历 —— 因为样本 HTML 现在 link 的是自写样式表，不读原表就没有可审的对象；
  同时这也让“匹配”与“样本用哪套 CSS”解耦（匹配只依赖 DOM）；
- 每条规则带 `ordinal`（在所属 sheet 内的序号），跨样本用 **`(sheet, media, ordinal)`** 合并、
  `matches` 取最大值。序号而不是选择器文本作为身份，正是为了避免 9.2-1 的吞噬；
- 输出 `out/css-audit.json`（规则、命中数、字节数、媒体上下文）。

样本集固定为五份（`npm run css:audit` 一条命令生成）：

| 样本 | 覆盖的构造 |
| --- | --- |
| `out/audit.html`（`test/features.md`） | h1–h6、任务列表、嵌套列表、对齐表格、行内/块公式、围栏、脚注、hr |
| `out/audit-toc.html`（`test/toc.md`） | `[TOC]`、多级标题、分页 |
| `out/audit-large.html`（`test/large.md`） | 多页、页眉页脚、长文档 |
| `out/audit-fence.html`（`test/fence.md`） | 多语言围栏、语法着色 |
| `out/audit-corpus.html`（`golden/typora-export-test.md`） | **图片块**、blockquote、`<ol start>` |

### 9.4 生成器 `tools/build-css.mjs`

输出两个文件（都带自述头注释）：

- `vendor/style/doc.css`（12,732 B，72 body + 6 print 规则）← `base.css` 的 live 规则；
- `vendor/style/code.css`（5,606 B，31 规则）← `codemirror.css` 的 live 规则，
  末尾追加一条手写规则 `.cm-s-inner .CodeMirror-vscrollbar{display:none!important}`
  （打印时滚动条不该占位，原来来自 `base-control.css`）。

两个关键实现点：

```js
// 1) 按 ordinal 输出，保持源码顺序（层叠依赖它）
const ordered = [...buckets.values()].flat().sort((a, b) => a.ordinal - b.ordinal);

// 2) 分节只贡献注释：第一次进入某节时插注释，规则仍在原位
if (name !== current) { out.push(`/* ==== ${name} ==== */`); current = name; }
```

分节（文档骨架 / 排版：标题 / 排版：正文与行内 / 排版：列表 / 排版：表格 /
脚注与导出细节 / 表单控件 / 其他）是本项目自有的组织方式，不改变任何声明与顺序。

### 9.5 原文移出分发包

| 文件 | 原位置 | 现位置 | 是否随包分发 |
| --- | --- | --- | --- |
| `base.css` | `vendor/style/` | `evidence/css-originals/` | 否 |
| `codemirror.css` | `vendor/style/` | `evidence/css-originals/` | 否 |
| `typora-base.css` | `src/fence/assets/style/` | `evidence/fence-originals/` | 否 |
| `typora-codemirror.css` | `src/fence/assets/style/` | `evidence/fence-originals/` | 否 |
| `user-theme-metrics.css` | `src/fence/assets/style/` | 删除（改由 `vendor/themes/my.css` 提供） | — |
| `typora-base-control-subset.css` | `src/fence/assets/style/` | 删除（规则并入 `code.css`） | — |

`src/fence/index.js` 的 `FENCE_STYLES` 由 4 项改为 `[doc.css, code.css, my.css]`；
`src/build.js` 的 `fenceExtraCss()` 不再注入任何 Typora 片段（文档本身已链接这三份）。
打包后 `app.asar` 里只剩：

```
\vendor\style\doc.css
\vendor\style\code.css
\vendor\themes\my.css
```

## 证据位置

- 原始样式表（只作审计输入，不分发）：`evidence\css-originals\base.css`、`codemirror.css`
- 审计结果：`out\css-audit.json`（含每条规则的 `matches`、`media`、`ordinal`）
- 生成产物：`vendor\style\doc.css`、`vendor\style\code.css`
- 生成脚本：`tools\css-audit.mjs`、`tools\build-css.mjs`
- 计算样式差异工具：`tools\_css-diff.mjs`（逐元素比较全部 computed property，用于 9.2 的定位）
- 引用改动：`src\build.js`（`styleLinks`）、`src\fence\index.js`（`FENCE_STYLES`）

## 验证

```powershell
npm run css:audit      # 生成五份样本 + 审计
npm run css:build      # 重新生成 doc.css / code.css
npm test               # fence 14/14、math 17/17、parity、acceptance、toc
node tools\acceptance.mjs --out out\css-v9.pdf   # 15/15 PASS，pixel 0.0000%
```

- 金标准文档：**15/15 PASS，`diff_body 0.0000%`、`diff_total 0.0000%`**，
  链接注释 rect / 书签 / 元数据全一致。
- 围栏渲染：`node src/fence/verify.js` **14/14 PASS**（含与真实 Typora 导出逐字节相同的那例）。
- 打包版：`dist\md2pdf-win32-x64\md2pdf.exe` 输出同样 15/15、0.0000%，体积仍 **209.7 MB**。

失败过的中间版本（供复核）：`out\css-v1.pdf` ~ `out\css-v5.pdf` 均为 `diff_body 4.0683%`
（缺 `p{orphans:4}`、`.CodeMirror{position:relative}`、`img{max-width:100%}` 等），
修复过程见 `tools\_css-diff.mjs` 的差异清单（121 → 25 → 16 → 0 条）。

## 决策

1. **不手写“等价 CSS”，而是生成**：逐条实测命中后再保留，避免凭感觉重写导致像素漂移；
   生成物同时天然带有“为什么保留这条”的证据链。
2. **规则身份用序号、输出用源码顺序**，因为 CSS 层叠语义依赖顺序（9.2）。
3. **样本集固定为五份且含图片**，缺一类构造就会静默删掉相关规则（9.2-3 的教训）。
4. **原文移出 `vendor/`、放进 `evidence/`**：审计仍然可复现，但分发包里不含第三方样式表原文。
5. **`my.css`（用户主题）继续随包**：它是用户自己的文件，本来就该被分发。

## 未解决风险

- **衍生作品的边界**：`doc.css`/`code.css` 是从 Typora 样式表实测筛选并重排得到的声明集合，
  选择器名（`.typora-export`、`.CodeMirror-*`、`#write` 等）属于 DOM 契约不能改。
  这仍然是一份“派生数据”，只是不再含原文的注释、分节与失效规则。
  若要进一步降低风险，只能改写 DOM 契约本身 —— 那会破坏与 Typora 的像素一致性，
  因此没有做。`my.css` 属于用户，不受此限。
- **换主题需要重跑审计**：live 集合是相对 `my.css` 与打印态 DOM 的。若换成 `github.css`
  等主题，部分被判“命中 0”的规则可能重新变成必需（例如主题若给标题定义 `::after`），
  此时必须重跑 `css:audit` + `css:build` 并重做像素验收。
- **样本覆盖仍可能不足**：五份样本没有覆盖定义列表、HTML 块、脚注多行、嵌套表格等构造；
  这些构造若依赖某条被判“命中 0”的规则，就会出现与 9.2-3 相同的静默缺失。
  新增构造时应当先往审计样本里加用例，再重新生成。
